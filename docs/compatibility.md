이 문서는 Electron 프로토타입 당시의 계획입니다. 현재 WPF 버전은 확장 기능을 지원하지 않으며 아래 계획은 현재 개발 약속이 아닙니다.

# 호환성 구현 계획

## 원칙

Deckboard 프로세스 없이 MacDock 한 앱에서 실행한다. 독 UI, 기본 액션 엔진, 확장 호스트를 분리한다. 원본 앱의 전체 소스 공개 여부와 별개로 공개 SDK의 동작 계약을 검토하며 구현한다.

## 현재 근거

- 공식 SDK: https://github.com/rivafarabi/deckboard-kit
- 확장 목록: https://github.com/rivafarabi/deckboard-extensions
- 공개 Extension 클래스: `inputs`, `selections`, `configs`, `execute(action, params)`
- 자체 fixture로 로드/액션 호출 계약만 검증. 외부 확장의 전체 호환성을 의미하지 않는다.

## 우선순위

1. 독 실행/모니터 이동/혼합 DPI/확대/많은 버튼 검증
2. 확장 실행을 별도 프로세스로 분리, 타임아웃·충돌·종료 처리
3. 확장별 메타데이터/설정/UI 입력 타입, 인증 저장소 및 패키지 설치
4. 실제 대표 확장 3종 선정 후 설치/초기화/실행/상태 변화 검증
5. OBS 등 내장 연동 및 키보드 외 복합 액션 (키 매크로/미디어는 구현됨)
6. 기존 보드 데이터의 읽기 전용 형식 조사 및 선택적 가져오기

## 명시적 한계

현재 `.asar` 다운로드 카탈로그, OAuth, 확장 동적 버튼 상태, 원본 아이콘 폰트, 자동 확장 재로드, 보드 가져오기를 지원하지 않는다. 확장 설정(`configs`)이 필요한 패키지는 오류로 표시한다. 타사 확장은 프로세스를 멈추거나 종료할 수 있으므로 초기 버전에서는 신뢰할 수 있는 테스트 확장으로만 검증한다.
